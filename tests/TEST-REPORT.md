# 1.3.0 验证报告

最终脚本在 **Edge 152.0.4191.66** 的本地夹具测试中通过全部功能回归。该版本与用户报告的 Edge 一致，但测试没有使用用户登录态，也没有运行网站本身的应用代码。

## 功能回归

运行 `node tests/run.cjs`，全部通过：

- ChatGPT / AI Studio 两种结构各 600 条消息：离屏渲染、原生导航位置、滚动高度、宽度变化、复制按钮、流式更新、SPA、bfcache、暂停恢复和重复注入。
- 自有导航默认不挂载，主动开启后跳转和历史前插有效；20 次退格删除最后一字，编辑器占位重建没有引入编辑器子树查询或全页扫描。
- 启动和普通持续输入中有受限优化进度；组合输入阶段暂停新增观察与提交，结束后恢复。组合输入期间编辑器直接被替换也能恢复。
- 零空闲额度、超时任务、每批登记 / 提交上限、隐藏页面、巨型代码块、1800 个观察目标上限、变更记录溢出和定时器降级。
- 历史文本保留同一 Text 节点原位修改后，优化高度与自然高度相符；正文进入编辑态后撤回优化。

组合输入用合成 composition 事件验证调度协议，不代表已实测操作系统输入法候选窗。复制验证的是页面按钮事件，不涉及系统剪贴板。

## 性能对照：只能解释这个压力模型

`input-benchmark.cjs` 使用 200 条消息、4 倍 CPU 降速，交错运行无脚本、1.2、新版，每种模式两轮。每轮分别测量刚注入与优化完成后，各包含 6 次输入和 6 次退格。输入刻意改变继承字距，迫使历史正文重排；这不是两个网站的真实实现。

下表列出两轮结果范围，不挑选最好的一次：

| 指标 | 无脚本 | 1.2.0 | 1.3.0 |
| --- | ---: | ---: | ---: |
| 启动阶段：每轮输入到帧后任务时间的中位数 | 1869.9–1884.5ms | 324.2–686.7ms | 216.1–732.3ms |
| 启动阶段：每轮累计布局时间 | 2846.22–2943.36ms | 1415.63–1439.01ms | 1071.64–1559.52ms |
| 优化完成后：每轮输入到帧后任务时间的中位数 | 760.5–1067.3ms | 39.9–43.6ms | 38.7–43.9ms |
| 脚本注入耗时（包含预热） | — | 7.5–8.1ms | 17.3–17.9ms |

新版通过增加少量前期预热，争取更早降低后续渲染成本；**启动样本波动较大，与 1.2 的范围重叠，不能证明每次启动都更快**。优化完成后的结果与 1.2 接近，两者在此模型中都明显优于无脚本。只有两轮样本，没有统计显著性结论，也不据此宣称真实网站提速倍数。

输入到帧后任务时间是近似响应指标，包含任务排队，**不是 INP，也不是精确的像素呈现时间**。启动测量从注入后开始，不包含网站首次下载 / 挂载；注入自身耗时另列。GPU、内存、宿主框架计算和实际会话结构可能改变结果。

原始样本保存在 [input-benchmark-results.json](input-benchmark-results.json)。报告中的源码 SHA-256 与最终脚本核对一致：

`38e7c580d1058308815cf403e3fe2e50205df5b593280ba61d4e9ceaa7d4f33c`

`input-benchmark-paused-draft.json` 保留了早期“普通输入完全停工”方案的失败对照，供后续维护参考；该策略没有交付。归档的 1.2 脚本只用于测试，不应同时安装。
